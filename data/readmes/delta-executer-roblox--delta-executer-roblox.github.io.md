# Delta Executor

Статический сайт в тематике Roblox и Luau: сведения о проекте, гайд, FAQ и карточка загрузки. HTML, CSS и обычный JavaScript, без npm и серверной части. Страница адаптируется к мобильным устройствам; эффекты учитывают настройку уменьшения движения.

## Публикация на GitHub Pages

1. Создайте отдельный репозиторий для Delta. Для GitHub Free используйте публичный репозиторий.
2. Загрузите **всё содержимое этой папки** в корень ветки `main`, включая `.github/workflows/pages.yml`, `scripts/`, `assets/` и `.nojekyll`. Не помещайте сайт во вложенную папку `Delta-Executor` внутри репозитория. Убедитесь, что скрытая папка `.github` попала в коммит.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Publish GitHub Pages → Run workflow**. Следующие коммиты в `main` будут публиковаться автоматически. При другом имени основной ветки замените `main` в `pages.yml`.
5. Дождитесь успешных задач `build` и `deploy`. Настоящий адрес сайта появится в **Settings → Pages** и в результате deployment.

Сборка получает адрес от GitHub Pages автоматически. Для проектного сайта учитывается путь репозитория: `/Delta-Executor/`. Ручная подстановка логина в HTML не нужна. Canonical, Open Graph, социальная карточка, sitemap и ссылка с 404 используют один фактический адрес. При смене домена в настройках Pages запустите workflow повторно. Настройте HTTPS в Pages.

Публикуется только папка `_site`: страницы, стили, JavaScript, изображения, шрифты и служебные файлы индексации. README, Python, PowerShell и `.github` не входят в сайт. Секреты, токены и пароли в `config.js` размещать нельзя: этот файл доступен посетителям.

## Файл для скачивания и данные релиза

Заполните `config.js`, сохраняя формат JSON внутри `window.SITE_CONFIG = { ... };`: двойные кавычки, без комментариев и завершающей запятой. Все значения — строки.

| Поле | Что указать |
| --- | --- |
| `product` | Название проекта |
| `downloadUrl` | Прямая HTTPS-ссылка на файл, например asset из GitHub Releases |
| `releaseUrl` | HTTPS-ссылка на страницу конкретного релиза |
| `version` | Фактический номер выпуска |
| `platform` | Подтверждённая платформа этой сборки |
| `fileName` | Точное имя файла с расширением |
| `fileSize` | Размер файла, например `24.8 MB` |
| `sha256` | Контрольная сумма из 64 шестнадцатеричных символов |
| `siteUrl` | Для ручной сборки: фактический HTTPS-адрес сайта с путём репозитория; в Actions определяется автоматически |

Пока `downloadUrl` пуст, сайт сообщает, что файл ещё не опубликован. После заполнения и новой публикации ссылки и сведения попадут в готовый HTML: скачивание работает без JavaScript. Файл открывается на указанном хостинге; имя при загрузке может определяться его HTTP-заголовками. Крупные архивы храните в **Releases**, не в папке сайта.

В PowerShell вычислить сумму реального файла можно командой `Get-FileHash -Algorithm SHA256 -LiteralPath 'C:\path\release.zip'`. SHA-256 подтверждает совпадение файлов. Заявление о безопасности относится к автору проекта; размещение на GitHub само по себе не является аудитом. Метка Verified проверяет подпись коммита.

## Локальная подготовка

Для просмотра исходного макета можно открыть `index.html`. Для проверки готовой публикации нужен Python 3.10+; дополнительные пакеты не требуются. При публикации через Actions устанавливать Python на свой компьютер не нужно.

Укажите реальный адрес в `config.js`, затем запустите из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-seo.ps1
python -m http.server 8080 --directory .\_site
```

Откройте `http://localhost:8080`. Можно передать адрес параметром `-SiteUrl`, а путь к Python — `-Python`. Кроссплатформенный эквивалент: `python scripts/build_site.py`. Параметр `--site-url` имеет приоритет над `config.js`. Папка `_site` целиком пересоздаётся при каждой сборке; не храните в ней исходники. Сам `index.html` и исходный `config.js` скрипт не изменяет. Не коммитьте `_site` и Python `__pycache__`.

Альтернативный ручной хостинг: загрузите содержимое готовой `_site`, включая `.nojekyll`. Для GitHub Pages рекомендуется встроенный workflow, чтобы адрес и метаданные не устаревали.

## Индексация и продвижение

- Меняйте `title` и `meta name="description"` в `index.html`. Сборка синхронизирует с ними социальные метаданные и описание SoftwareApplication. Не добавляйте выдуманные рейтинги, отзывы или результаты проверок.
- Изображение предпросмотра: `assets/social-card.png`, размер **1200 × 630**. Сборка добавляет его абсолютный адрес в Open Graph и Twitter Card. Если файла нет, используется обычная текстовая карточка. Реальные снимки программы можно добавить отдельно, с понятными `alt` и размерами.
- После публикации добавьте точный URL сайта в Google Search Console и Яндекс Вебмастер. Для Pages на общем хосте используйте URL-prefix свойство, включающее путь репозитория; доступен способ подтверждения через HTML-метатег в `<head>`. Отправьте опубликованный `sitemap.xml` и проверьте главную страницу инструментом проверки URL.
- `robots.txt` действует только по адресу **в корне хоста**. Файл `username.github.io/Delta-Executor/robots.txt` не управляет обходом всего домена. Для проектного сайта отправьте sitemap напрямую в инструментах вебмастера. При наличии сайта `username.github.io` его корневой robots должен разрешать обход обоих проектов.
- Дополняйте страницу полезными сведениями о собственном проекте: подтверждёнными требованиями, реальными снимками, изменениями по версиям и ответами на вопросы. У Delta и Xeno должны оставаться самостоятельные описания. Поддерживайте ссылку из README репозитория на опубликованный сайт и с сайта на актуальный релиз.
- После публикации проверьте сайт на телефоне, клавиатурную навигацию, загрузку файла, метаданные, мобильную скорость и переход на главную с вложенного ошибочного адреса. Индексация и позиция в поиске зависят от поисковых систем; техническая настройка не гарантирует первое место.
