# 衡知

看见每一笔决策。

![管理台、展示页、决策详情、数据与因子](docs/images/desk-grid.png)

本机（或一台小服务器）上的个人 AI 交易复盘台：一个模型、一套提示词，只做币安 USDT-M 永续。模型决定开平方向和价位；代码只做仓位/杠杆裁剪和交易所必拒，只缩小不放大。资金和仓位以币安为准。

不保证赚钱。通用模型做交易，亏是常态。默认测试网。正式网必须在设置里确认，或在 `.env` 写 `I_UNDERSTAND_MAINNET=yes`。

## 赌徒的忏悔

我把它开源，不是因为它赚到了钱。

合约带杠杆。模型会错。错了就是真金。上面截图里的回撤不是演示。

如果你是来找「AI 帮你稳稳发财」的：关掉这个页面。钱不够亏的，不要开正式网。够亏的，先问自己是不是想看清每一笔为什么亏，而不是想翻本。

衡知只让你看见决策。它不保证下一笔是对的。也不该被当成提款机。

## 它做什么

- 按你设的间隔决策（默认 10 分钟），新闻或结构异动会提前叫醒
- 开仓必须带止损和止盈，条件单挂在币安（含 Algo 止损）
- 每轮结论可回放：提示词、模型原文、风控通过/驳回、成交
- 游客页只看权益和决策；`/desk` 改密钥、启停、平仓
- 「预测」走同一模型同一提示词，过风控但不下单
- 换币安账户会按新账户重新起算权益和熔断，不把上一户的数混进来

## 它不做什么

- 不做多租户 SaaS、第二家交易所、本地假账本
- 不做多模型竞技、回测主路径、部分平仓摊薄
- 生产路径禁止 MOCK 成交
- 代码不会替模型编一个止盈价，也不会把仓位放大

## 警告

这是实盘交易软件。你可能亏光本金。密钥不要提交到 Git。正式网 API **只要合约交易，不要开提现**。白名单只写这台机器的出口 IP。

## 要求

- Python 3.11+
- Node 20+（打包管理台）
- 兼容 OpenAI Responses API 的模型网关（`/v1/responses`）
- 币安合约测试网或正式网 API Key

## 启动

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env

cd frontend
npm install
npm run build
cd ..

python -m app
```

打开 http://127.0.0.1:8000 。本机没设管理密码时，打开就是管理台。设了 `DESK_PASSWORD` 之后，根路径是游客展示，管理台在 `/desk`。

实盘用 `python -m app`，**不要加 `--reload`**。改 Python 文件会重启进程，进行中的决策会被掐掉。改前端后重新 `npm run build`。

开发页面可以另开 `cd frontend && npm run dev`（默认 5173），但入口仍是后端。带 lifespan 的正式应用不要用测试去打 `data/aibi.db`。

## 配置

复制 `.env.example`。常用项：

| 变量 | 含义 |
| --- | --- |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 模型网关。协议固定 Responses API |
| `LLM_REASONING_EFFORT` | `low` / `medium` / `high` / `xhigh`。高推理可能要想几分钟 |
| `BINANCE_NETWORK` | `testnet` 或 `mainnet` |
| `BINANCE_TESTNET_*` / `BINANCE_MAINNET_*` | 两套密钥分开填，不要混用 |
| `I_UNDERSTAND_MAINNET` | 正式网必须 `yes` |
| `CYCLE_MINUTES` | 例行决策间隔，1–60 |
| `DESK_PASSWORD` | 管理台密码。对外网卡监听时必填 |
| `TESTNET_ALLOC_USDT` / `MAINNET_ALLOC_USDT` | 分给 AI 的保证金上限，`0` 为不限制 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 可选值班铃 |

测试网申请：https://testnet.binancefuture.com  
正式网只勾「允许合约交易」。现货权限不够。衡知打的是 `fapi.binance.com`。

设置里填完密钥后先点测试。短测试「你好」能过，不代表决策请求也能过：高推理中间没数据包时，有的网关会掐 TCP，本仓库决策走流式收包。

## 仓位硬闸

设置页只读。代码按工作权益裁，不改模型的方向和止损/止盈价：

- 单笔风险约 1%
- 杠杆顶 8x
- 最多 4 个仓
- 保证金合计不超过约 40%
- 组合风险约 3%

当日亏损或回撤过大触发熔断：暂停新开仓，已有仓可平或改挂单。

## 部署

后端默认只听 `127.0.0.1:8000`，前面用 Nginx 或 Caddy。`HOST` 若不是本机回环，必须设 `DESK_PASSWORD`，否则拒绝启动。

模板：`deploy/nginx.conf`、`deploy/caddy.snippet`、`deploy/hengzhi.service`。

```bash
cd frontend && npm run build
# 用 systemd 跑 /opt/hengzhi/.venv/bin/python -m app
# 不要把 8000 直接暴露到公网
```

进程会：交易或仅预测已开则启动后立刻跑一轮；SQLite 热备份到 `data/backups/`（约 6 小时一份，留 8 份）；超过 20 分钟无决策可走 Telegram 告警。

覆盖正式库必须先停交易，再恢复，然后重启进程。

## 测试

```bash
pytest -q
```
