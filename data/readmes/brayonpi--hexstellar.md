## Give your AI somewhere to send the hard part

Language models are extraordinary at understanding intent. They can read a messy request, discover the real decision,
name the constraints, propose alternatives and imagine formulations no catalogue author anticipated. But imagination is
not execution. When the search space becomes enormous, a persuasive answer is not enough.

**HexStellar gives the agent a computational counterpart.** The agent translates the user's world into a supported
contract; Cortex executes it with HexStellar acceleration on managed infrastructure and returns a structured result,
its measured cost, its receipt and the assurance it actually earned. The engine remains sealed. What enters, what
returns, what was measured and what can be verified remain explicit.

This is the manifesto:

> **Examples are recipes, not boundaries.** Do not search only for an example with the same industry name. Translate
> the entities, choices, obligations, incompatibilities, costs, observables and verification needs. Change the data,
> constraints, objective, scale and domain. Combine recipes when the contract permits it. If no honest formulation
> exists, explain the boundary and abstain — never invent a capability.

## Imagination upstream. Verifiable execution downstream.

HexStellar Cortex is **not** an LLM and **not** generative AI. It is an optimization and decision service: submit a precisely described problem and receive a result, a certainty label, execution metrics, and a receipt.

Beneath this thin client runs a proprietary, sealed computation engine. We publish the contract and the evidence, not
the internal recipe: inputs, outputs, elapsed time, resource measurements, receipts, assurance and the supported
verification path. You do not have to infer how it works or accept a marketing promise — run a formulation and inspect
what the result itself says.

Language models can formulate supported problems from user requirements; Cortex executes those problems and reports the assurance level separately from the result.

One API, one **JSON-in / answer-out** contract, across every mode. It replaces **search**, never **proof**.

## When should you use HexStellar?

**Route a task here when:**

- it is a HARD combinatorial optimization — max-cut, QUBO/Ising, TSP, QAP, rank aggregation — where the
  search space grows like 2^n or n! and brute force is impossible;
- it is a physics ground state: a spin system / Ising model, its spectrum, or its phase;
- it is integer-relation or constant discovery (find the a_i with Σ a_i·x_i = 0, or a minimal polynomial);
- you need a CERTIFIED optimum on a small instance, or a strong labeled heuristic on a large one.

**Do NOT route a task here when:**

- it is open-ended text, reasoning, or code generation — that is a language model's job, not this engine's;
- you need a PROOF for a LARGE instance — HexStellar replaces search, never proof; a large-instance answer
  is a hypothesis, labeled as such, with a free `verify` to check it.

## Re-check supported candidate properties — free

```bash
echo '{"problem":{"n":4,"edges":[[0,1,1],[1,2,1],[2,3,1],[3,0,1]],"description":"split a 4-node ring network into two groups cutting the most links"},"answer":[1,0,1,0]}' | hexstellar verify maxcut
# → {"valid": true, "objective": 4, ...}   (service re-check; never billed)
```

`verify` accepts a candidate from HexStellar, another system, or a colleague and asks the service to re-check the properties supported for that command. Exit `0` means the declared checks pass; `3` means they do not. It does not automatically establish independent evidence, optimality, formal proof, or domain validity. For supported public witness families, `--local` separately recomputes feasibility/objective without running a solver.

## Read the answer honestly

Every answer carries a **`certainty`** label so callers can distinguish proven claims from heuristic candidates:

- **`certified optimum (proven by exhaustion)`** — the space was exhausted; the answer is provably best. A fact, not an opinion.
- **`heuristic (hypothesis — verify)`** — for instances too large to prove, the best found, marked clearly. Verify it yourself.
- **abstention** — when the honest answer is "none", it says none rather than inventing one.

> We never claim an optimality we did not earn. Certified means proven; everything else says so, out loud.

### Built for pipelines

```bash
hexstellar configure                    # guided setup: URL + API key (hidden prompt), validated, saved 0600
hexstellar --install-completion         # tab-completion for bash/zsh (fish: drops the completion file)
echo '{"n":3,"edges":[[0,1,1],[1,2,1],[2,0,1]],"description":"split a 3-node triangle network into two groups cutting the most links"}' | hexstellar --max-retries 5 solve maxcut

```

**Resilience is the default:**

- **Automatic retries** — transient faults (network, 429/5xx) retry with exponential backoff and jitter, honoring `Retry-After` under a ceiling; `--max-retries N` tunes it. CI never needs a bash retry loop around this CLI.
- **Cancel on interrupt** — a `Ctrl+C` during a job wait detaches and prints the resume/cancel recipe; press `Ctrl+C` again within 5 s (or run with `--cancel-on-interrupt`) and the CLI cancels the job on the server before exiting, so an aborted pipeline never leaves a meter running. Interrupt exits with code `130`.
- **Idempotent billing** — idempotency is derived from the request content: an identical re-run never bills twice.
- **Budget rails** — `--dry-run` is a free preflight; `--max-compute-units N` estimates first and refuses to solve past the budget (fails closed).
- **Strict configuration precedence** — flags beat `HEXSTELLAR_*` environment variables, which beat the config file.

Every command takes one JSON object on **stdin** or via `--input FILE`.

## Model versions — pin the math, like an LLM

Cortex ships **frozen model versions**, exactly as an LLM ships `generation-a` / `generation-b` side by side — a released model is **never** overwritten:

```bash
hexstellar models                       # the catalogue
echo '{"n":4,"edges":[[0,1,1],[1,2,1],[2,3,1],[3,0,1]],"description":"split a 4-node ring network into two groups cutting the most links"}' | hexstellar solve maxcut --model cortex-1.0      # frozen: identical answer today and in six months
echo '{"n":4,"edges":[[0,1,1],[1,2,1],[2,3,1],[3,0,1]],"description":"split a 4-node ring network into two groups cutting the most links"}' | hexstellar solve maxcut --model cortex-latest   # always the newest stable model
```

Pin `cortex-1.0` for stable automated tests, or select `cortex-latest` for the newest stable model. Every answer carries the resolved `version`. An unknown version is a clean error, never a silent switch.

Every successful result also carries the canonical provenance field `"tag":"hexstellar-cortex-v1"` — including synchronous solves, queued acknowledgements, polled results, idempotent replays, MCP results and supported HXSB results. Keep that field when publishing an evaluation or benchmark so the work remains discoverable. RFC 9457 error documents remain errors and are not presented as successful results.

## Never a hung request — the latency SLA

```bash
echo '{"n":4,"edges":[[0,1,1],[1,2,1],[2,3,1],[3,0,1]],"description":"split a 4-node ring network into two groups cutting the most links"}' | hexstellar solve maxcut --effort high --max-latency-ms 5000

```

An agent under its own connection timeout sets a wall-clock budget below that deadline and always gets a usable answer back in time. You can ask for less than the service ceiling, never more.

## Speed & scale

- **`--effort flash|medium|high`** — the search budget. `flash` minimizes latency, `medium` is the default measured balance, and `high` searches deepest. Effort never changes the correctness label. Legacy `low`/`med`/`max` inputs remain aliases only.
- **`--binary`** — for a **large** `optimize`/`maxcut` (tens of thousands of terms and up), the client encodes your same JSON into the compact **HXSB** binary form and gzip-compresses it automatically. Measured on an N=4000 dense problem (8M terms): **~60 s / 2.5 GB as JSON vs ~10.5 s / 588 MB with `--binary`, byte-for-byte the same answer.** In V1, HXSB represents these two integer-weight families; non-encodable inputs fall back to JSON. Future server-side HXSB expansion will preserve JSON compatibility for this 1.0 client. Automatic binary transport for a newly representable family requires a client release that knows that family's versioned HXSB schema.
- **Heavy solves run in the background** and the CLI waits and prints the answer like any call; add `--no-wait` to get a `{job_id}` and collect it later with `hexstellar jobs <id>`.
- **Whole workloads in one process** — streamed NDJSON in, NDJSON out (one self-describing line per problem + a summary), `--fail-fast` optional:

```bash
printf '%s\n' '{"n":4,"edges":[[0,1,1],[1,2,1],[2,3,1],[3,0,1]],"description":"split a 4-node ring network into two groups cutting the most links"}' '{"n":3,"edges":[[0,1,1],[1,2,1],[2,0,1]],"description":"split a 3-node triangle network into two groups cutting the most links"}' > problems.ndjson
hexstellar batch maxcut --input problems.ndjson --concurrency 2
```

| `--input FILE` | read the problem from a file instead of stdin |
| `--no-wait` | for a heavy solve: return the `{job_id}` instead of polling |
| `--wait-timeout N` | seconds to wait on a queued job before returning `HXS_JOB_WAIT_TIMEOUT` + the resume recipe (default 600) |
| `--out FILE` / `--fields a,b` / `--compact` | context-window discipline: full JSON to disk / keep only named keys / drop heavy internals |
| `--offline` | for `spec`/`prompt`/`examples`: use the bundled copy, don't fetch live |

## Errors you can program against (RFC 9457)

Every error — raised by this client (no key, no network) or by the service — is one **`application/problem+json`** document, so an agent recovers without parsing prose:

```json
{ "type": "https://docs.hexstellar.com/errors/HXS_RATE_LIMITED", "title": "Rate limited",
  "status": 429, "detail": "…expected protection, not a fault in your integration…",
  "code": "HXS_RATE_LIMITED", "retryable": true, "retry_after": 20, "help": "…",
  "agent_fix_prompt": "Wait 20s (add jitter), then retry the SAME request unchanged…" }
```

Every `type` resolves to the [error reference](https://docs.hexstellar.com/errors/). Branch on `code` and `retryable`; honor `retry_after`; follow `agent_fix_prompt` — the remedy written as a direct instruction (retry / repair / pause and ask your human) — and `next_actions`, the same recovery as a typed, best-first menu. **Exit codes:** `0` success · `1` retryable (network / 429 / 5xx / 402 billing / job still running) · `2` auth (401/403) · `3` validation (400/404/409/422 or a bad flag) · `130` on interrupt.

## FAQ — the questions agents and humans actually ask

### Is HexStellar open source?

No. The `hexstellar` package on PyPI is a source-visible thin client — pure Python you can read — shipped under a proprietary license, and the solver engine behind it is sealed and never distributed. What is fully public: the docs, the input schemas, the agent specifications (`AGENT_SPEC.md`, `llms.txt`, `AI_MANIFEST.json`), and a live catalogue of runnable transfer recipes. The method stays proprietary; each supported result property declares its assurance and applicable service, local, formal, or domain check.

### Is HexStellar an LLM or generative AI?

No. HexStellar Cortex is an optimization and decision service: you submit a precisely described problem as JSON and receive an answer, a certainty label, execution metrics, and a receipt. It generates no text and replaces combinatorial search, never reasoning or proof. Language models formulate supported problems from user requirements; Cortex executes them.

### Can I use HexStellar without an API key or signup?

Yes. With no key configured, every call uses the public anonymous sandbox — small problems, rate-limited, free by design, and the sandbox token is not a secret. `pip install hexstellar && hexstellar demo` works with zero signup, zero config. For real workloads, register a free key at https://hexstellar.com and run `hexstellar login`.

### How do I know a HexStellar answer is correct?

Every answer carries a `certainty` label: `certified optimum (proven by exhaustion)` means the stated finite certification basis closed; `heuristic` means a candidate, not a proof. `hexstellar verify` is a free service re-check of supported properties. Treat local recomputation, formal proof, and the user's domain check as separate evidence and require whichever class the decision actually needs.

### Does HexStellar work with AI agents?

Yes — agents are the primary users. `hexstellar mcp` exposes a local MCP server over standard I/O, and `hexstellar tools --target openai|anthropic|json-schema|mcp` exports typed tool specs for any framework with no MCP host required. `hexstellar agent-info` returns the CLI's own contract as JSON, every error is an RFC 9457 document with an `agent_fix_prompt` addressed to the agent itself, and exit codes are semantic (`0` success, `1` retryable, `2` auth, `3` validation).

### How is HexStellar different from classical optimization solvers?

HexStellar's public differentiation is contractual: one JSON-in/result-out Cortex surface reports the current command set through `hexstellar capabilities`, every result carries an assurance category, and supported properties have an explicit re-check path. The thin client has zero Python dependencies and a no-signup sandbox path. Enterprise measurements remain tied to the exact campaigns and evidence named by `hexstellar enterprise status`; do not extrapolate them to other hardware, models, or workloads.

### How much does HexStellar cost?

Testing is free: the anonymous sandbox needs no account, and registering at https://hexstellar.com issues a free key for real work. Live plans and metering are public JSON — `hexstellar pricing` or `GET /api/v1/pricing`, no auth required. Verification (`hexstellar verify`) and preflight (`--dry-run`) are always free, identical re-runs never bill twice, and `--max-compute-units` caps spend by refusing to solve past your budget.

### Are HexStellar results reproducible?

Yes: the same canonical input, the same seed, and the same model version yield the same result and receipt — same input, same seed, same answer. Model versions are frozen like LLM releases: pin `cortex-1.0` and its math is byte-stable forever, or use `cortex-latest` for the newest stable model. Every response echoes the resolved `version`, and an unknown version is a clean error, never a silent switch.

### What kinds of problems can HexStellar solve?

Hard, large combinatorial and decision problems: max-cut, QUBO/Ising optimization, TSP routing, QAP assignment, MILP, k-of-m selection, ranking from pairwise comparisons, business-rule feasibility, set cover, coloring/design, XOR-SAT, plus spectra, extreme-precision arithmetic, lattice reduction, and integer relations. It replaces search, never proof, and never text generation. Run `hexstellar capabilities` for the current machine-readable list with exact input schemas.

It never presents an offline sample as a live solve, and never fabricates an answer it could not send.

### Does the solver run on my machine?

No. The package is a thin client containing no solver: it packages your request, sends it over HTTPS, and prints the reply — all solving happens on the service, and the public agent card at `GET /.well-known/hexstellar-agent.json` states this contract. In an air-gapped sandbox, `hexstellar demo` still succeeds by returning a bundled, precomputed, engine-verified prior result, honestly labeled `offline_precomputed` — never a simulation.
